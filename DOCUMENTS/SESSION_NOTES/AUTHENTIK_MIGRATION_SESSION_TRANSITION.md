### 1.5 User Management Gap Discovery — Critical

After completing Authelia deployment, evaluated the user management workflow and discovered critical gaps:

| Requirement | Authelia Support |
|-------------|-----------------|
| Admin UI for user management | ❌ None — manual YAML editing only |
| Admin UI for group management | ❌ None — manual YAML editing only |
| Create user via web interface | ❌ Requires SSH + CLI hash generation |
| Forced password change on first login | ❌ Not supported |
| Self-service password change (no SMTP) | ❌ Not supported |
| Self-service password reset | ⚠️ Requires SMTP configuration |

**The core problem:** Admin must generate password hash via CLI, manually edit YAML, restart Authelia, and communicate the password to the user — admin knows the user's password. No mechanism to force password change on first login. This is a security anti-pattern unacceptable even for a homelab.

### 1.6 Alternative Evaluation

| Tool | Admin UI | Temp Password + Forced Change | Self-Service Change (no SMTP) | RAM |
|------|----------|-------------------------------|-------------------------------|-----|
| Authelia | ❌ | ❌ | ❌ | ~30MB |
| lldap + Authelia | ✅ Users/groups | ❌ No forced change | ❌ | ~45MB |
| Authentik | ✅ Full | ✅ Native | ✅ Web UI | ~1.2GB |
| Keycloak | ✅ Full | ✅ Native | ✅ Web UI | ~1-2GB |

**Decision:** Migrate to Authentik. User management is not optional — admin UI, temporary passwords, and forced password change on first login are minimum requirements.

## 6. Lessons Learned

1. **User management is baseline, not nice-to-have.** Admin UI, temporary passwords, forced password change — these are minimum requirements for any multi-user auth system. Should have been primary evaluation criteria.

2. **Evaluate operational workflow, not just architecture.** Authelia's 30MB footprint was attractive, but the daily user management workflow (SSH + CLI + YAML + restart) is an operational burden that offsets the simplicity.

3. **Infrastructure work is reusable.** ForwardAuth pattern, DNS, tunnel routes, `forwardedHeaders` fix, Traefik middleware pattern — all carry forward to Authentik. The migration is contained to the auth service itself.

4. **Admin knowing passwords is a security anti-pattern.** Even in a homelab. The "forced password change on first login" flow is the proper pattern.

5. **Redis removal from Authentik (2025.10) changes the calculus.** The original rejection of Authentik cited 3+ containers including Redis. With Redis removed (PostgreSQL handles everything), it's now 2 containers + 1 PostgreSQL — still heavier than Authelia but more manageable.

6. **Deployment model matters.** Multi-container apps need CoreOS VM with Podman Quadlet, not LXC. Docker-in-LXC is an anti-pattern. This is why VM-316 replaces CT-316.

7. **PROD RUST_LOG=warn creates diagnostic blind spots.** Consider adding a structured startup log line at warn level: "Backend started, version X, Neo4j connected" — a single line that confirms health without verbose info logging.
